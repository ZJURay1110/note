    Python的内存分配¶

    1 机制内存驻留¶

    在 Python 中，内存驻留（Interning） 是一种极致的内存优化技术。它的核心逻辑是：对于某些频繁使用的不可变对象，系统只在内存中保留一份拷贝。 当多个变量指向相同的值时，Python 不会创建重复的对象，而是让这些变量全部指向同一个内存地址。这不仅节省了空间，还大大提升了比较速度（因为 is 的地址比较比 == 的值比较快得多）。

    1.1 整数驻留：小整数池 (Small Integer Caching)¶

    这是 Python 最广为人知的驻留机制。

    • 范围： [-5, 256]。
    • 逻辑： Python 认为这个范围内的整数极其常用（比如循环索引、函数返回值状态等）。因此，在 Python 解释器启动时，它就会预先在内存中创建好这些对象，并且永不销毁。
    • 实验： 
      a = 256
b = 256
print(a is b)  # True (在池子里，同一个对象)

c = 257
d = 257
print(c is d)  # False (超出了池子，通常会创建两个对象)

    1.2 字符串驻留 (String Interning)¶

    字符串的驻留规则比整数复杂一些，它主要为了提高字典（Dict）查找的效率（因为 Python 内部大量使用字符串作为字典的键）。

    1. 自动驻留的规则¶

    通常情况下，满足以下条件的字符串会被自动驻留： * 长度较短的字符串。 * 只包含标识符字符的字符串（字母、数字、下划线）。如果包含空格或特殊符号，通常不会自动驻留。 * 常量折叠： 在同一个代码块（如一个 .py 文件）中定义的相同字符串常量。

    2. 强制驻留¶

    可以通过 sys.intern() 手动强制 Python 驻留某个字符串。 

    import sys
s1 = sys.intern("hello world!")
s2 = sys.intern("hello world!")
print(s1 is s2)  # True (强制合并到了同一个地址)

    1.3 编译器优化：常量折叠 (Constant Folding)¶

    这是在上一条回复中遇到的情况（0.1 is 0.1 可能为 True）。

    当 Python 编译源代码到字节码时，它会扫描整个代码块。如果发现多个相同的字面量（如大整数、浮点数、长字符串），它会把它们合并为一个常量存储。

    • REPL (交互式环境)： 一行行编译，编译器看不到下一行的内容，所以不触发合并。
    • Script (.py文件)： 整个文件一起编译，编译器看到了重复的字面量，触发合并。

    1.4 只驻留“不可变”对象¶

    这是一个关键的设计哲学。只有不可变对象（int, str, tuple）才配拥有驻留机制。

    类型 驻留范围/条件 备注
    int -5 到 256 全局预创建，永不销毁
    str 标识符类字符、短字符串 主要为 Dict 键查找优化
    float 仅限同一代码块内的字面量 编译器层面的静态优化
    tuple 极少数空元组 () 只有内容全为不可变且触发优化时
    list / dict 从不驻留 因为它们是可变的

    2 各种数据类型的存储机制：引用与绑定¶

    “变量是标签，对象是盒子。”

    2.1 变量赋值的本质¶

    当写下 a = [1, 2, 3] 时，Python 并不是把这个列表存进了变量 a 里，而是： 1. 在内存中创建一个列表对象 [1, 2, 3]。 2. 把标签 a 贴到这个对象上。

    2.2 不可变对象 vs 可变对象的存储表现¶

    类型 代表 修改时的行为 内存表现
    不可变 (Immutable) int, str, tuple, float 重新绑定 产生一个新对象，变量指向新地址。旧对象若无引用则被回收。
    可变 (Mutable) list, dict, set, bytearray 原地修改 在原地址修改对象内容，变量指向的地址保持不变。

    实验：¶

    # 不可变对象：看似修改，实则换人
x = 10
print(id(x))
x = x + 1 
print(id(x))  # 地址变了！

# 可变对象：修修补补，还是原件
y = [1, 2]
print(id(y))
y.append(3)
print(id(y))  # 地址没变！

    2.3 引用计数与垃圾回收（GC）¶

    Python 内部使用 引用计数（Reference Counting） 来管理内存： * 每个对象都会记录“现在有多少个标签贴在我身上”。 * 当引用计数归零时，该对象占用的内存会被立即释放。 * 对于“循环引用”的情况（A 引用 B，B 引用 A），Python 会启动分代回收机制来处理。

    3 浅拷贝与深拷贝¶

    3.1 浅拷贝 (Shallow Copy)¶

    • 方法： list.copy(), dict.copy(), copy.copy(), 或者切片 [:]。
    • 原理： 创建一个新的容器对象，但内部填充的依然是原对象中元素的引用。
    • 风险： 如果列表中嵌套了其他可变对象（如列表里的列表），修改嵌套项会“穿透”到原对象。
    import copy
original = [1, [2, 3]]
shallow = copy.copy(original)

shallow[0] = 99      # 修改一级元素，原对象不受影响
shallow[1].append(4) # 修改二级嵌套，原对象被连带修改！
# original 变成 [1, [2, 3, 4]]

    3.2 深拷贝 (Deep Copy)¶

    • 方法： copy.deepcopy()。
    • 原理： 递归地拷贝对象中所有的层级。它会顺着引用一直找下去，把所有见到的对象都克隆一份新的。
    • 代价： 消耗更多的内存和 CPU 时间，且由于递归检测，速度比浅拷贝慢得多。
    deep = copy.deepcopy(original)
deep[1].append(5) # 无论怎么改，都与 original 无关了

    3.3 总结对比表¶

    特性 赋值 (b = a) 浅拷贝 (copy()) 深拷贝 (deepcopy())
    新对象 ID 相同 (同一对象) 不同 (新容器) 不同 (全套新对象)
    一级元素修改 互相影响 互不影响 互不影响
    嵌套元素修改 互相影响 互相影响 互不影响
    适用场景 传递引用，节省空间 复制简单数据结构 复制复杂嵌套数据、隔离状态

    4 id 与内存地址的关系¶

    4.1 id() 的本质¶

    id() 是 Python 的内置函数，返回一个对象的唯一标识符（一个整数）。

    • 唯一性：在同一个程序运行期间，每一个存在的对象都有一个唯一的 ID。
    • 生命周期：只要对象没被销毁，它的 ID 就不会变。如果对象被销毁了，它的 ID 可能会被后来创建的对象复用。

    4.2 CPython 中的内存映射¶

    虽然 Python 规范并没有强制要求 id() 必须是内存地址，但在我们最常用的 CPython（官方版本）中：

    id(obj) 返回的就是该对象在 C 语言层面存储的内存地址。

    可以通过十六进制转换，看到它和底层内存地址的对应关系： 

    a = [1, 2, 3]
print(id(a))          # 打印十进制 ID
print(hex(id(a)))     # 打印十六进制地址 (更像我们常说的内存地址)

    4.3 用 id 验证核心机制¶

    1. 验证“贴标签” (赋值)¶

    a = [1, 2, 3]
b = a
print(id(a) == id(b))  # True -> 地址完全一致，说明是同一个盒子

    2. 验证“小整数池” (驻留)¶

    x = 100
y = 100
print(id(x) == id(y))  # True -> 100 预存在池子里，x 和 y 都指向它

    3. 验证“不可变性” (重新绑定)¶

    s = "hello"
old_id = id(s)
s += " world"
new_id = id(s)
print(old_id == new_id) # False -> 字符串变了，地址也变了，生成了新对象

    4.4 is 运算符：id 的快捷键¶

    在 Python 中，is 运算符的本质就是比较两个对象的 id 是否相等。

    • a is b：等价于 id(a) == id(b)。检查它们是不是同一个对象（物理层面）。
    • a == b：检查它们的值是否相等（逻辑层面）。

    经典案例： 

    list1 = [1, 2]
list2 = [1, 2]
print(list1 == list2) # True  (值一样)
print(list1 is list2) # False (在内存中是两个不同的盒子，id 不同)

    4.5 性能与陷阱：ID 的复用¶

    警告： 不要依赖已经被销毁对象的 ID。 由于 Python 的内存优化机制，当一个对象被垃圾回收后，它的内存地址（ID）会立即空出来。如果紧接着创建一个新对象，它很可能会刚好拿到那个旧地址。

    # 这种情况在交互式终端中经常发生
print(id(500) == id(500)) # 可能会返回 True
# 过程：第一个 500 被创建后对比完立即销毁，第二个 500 恰好占用了同一块内存。

    4.6 总结¶

    概念 含义
    id(obj) 对象的“身份证号”，在 CPython 中就是内存地址。
    is 判断两者的 id 是否一致。
    == 判断两者的 内容 是否一致。
